# 구조 JSON 계약

`version: 1`의 JSON을 정본으로 사용한다. 입력 파일과 같은 디렉터리 또는 그 하위에 슬라이드·포스터·로컬 의존 파일을 둔다. 실행기가 정보를 요약하거나 사업 구조를 추론하지는 않는다. 에이전트가 실제 자료를 읽고 의미를 정한 뒤 이 구조에 기록한다.

```json
{
  "version": 1,
  "title": "제안 설명",
  "description": "청중과 발표 목적을 설명합니다.",
  "canvas": {
    "id": "board",
    "kind": "group",
    "title": "전체 제안",
    "layout": "grid",
    "columns": 2,
    "children": [
      {
        "id": "context",
        "kind": "group",
        "title": "해결할 문제",
        "summary": "문제와 근거를 함께 설명합니다.",
        "layout": "column",
        "children": [
          {
            "id": "problem",
            "kind": "slide",
            "title": "문제의 근거",
            "src": "slides/problem.svg",
            "format": "svg",
            "width": 1920,
            "height": 1080,
            "alt": "원본 슬라이드에서 전달하는 내용을 설명합니다.",
            "notes": "발표자가 이 장면에서 설명할 내용을 적습니다."
          }
        ]
      }
    ]
  },
  "paths": [
    {
      "id": "main",
      "title": "기본 설명",
      "steps": [
        {"target": "problem", "label": "문제와 근거", "duration": 450}
      ]
    }
  ],
  "defaultPath": "main"
}
```

## 독립적인 세 계층

1. `canvas.children`의 중첩은 **내용의 포함 관계**이다. 목차와 상위 그룹 이동이 이 구조를 사용한다.
2. 그룹별 `layout`은 **그룹 내부의 공간 배치**이다. 모든 그룹을 같은 방식으로 놓을 필요가 없다.
3. `paths[].steps`는 **발표 시점의 슬라이드 순서**이다. 각 단계에는 슬라이드 ID만 넣는다. 전체 윤곽과 그룹 확대는 탐색용 보기이며 발표 단계가 아니다. 트리의 연결선이 발표 순서를 자동으로 결정하지 않는다.

## 배치

| layout | 동작 | 선택 기준 |
|---|---|---|
| `row` | 자식을 왼쪽에서 오른쪽으로 배치한다. | 짧은 순서, 병렬 비교 |
| `column` | 위에서 아래로 배치한다. | 단계 설명, 세로 순차 발표 |
| `grid` | 열 수에 맞춰 배치한다. `columns` 기본값은 2이다. | 비슷한 중요도의 묶음 |
| `tree` | 첫 자식을 루트로 놓고, 나머지 자식을 아래의 가지로 놓는다. 하위 그룹에서 재귀적으로 반복할 수 있다. 구조 연결선을 생성한다. | 실제 상하 관계나 분해 관계가 있는 자료 |
| `free` | 각 자식의 `position: {x, y}`를 사용한다. | 지도, 비대칭 구성, 직접 설계한 공간 |

`tree`는 임의 DAG 최적화 엔진이 아니다. 첫 자식을 루트로 해석할 의미적 근거가 있어야 한다. 격자에 선만 추가해 트리라고 부르지 않는다. `free`의 좌표는 해당 부모 내부의 배치 좌표이며 음수는 허용하지 않는다. 다른 layout에서는 자식 `position`을 지정하지 않는다.

그룹은 `gap`을 조절할 수 있으며 기본값은 40이다. `color`는 `#hex`만 받는다. 그룹 수를 3개나 특정 업무 분류로 고정하지 않는다. 최대 중첩 깊이는 12이다.

## 미디어

- `format`: `svg`, `png`, `html`이다. 파일 확장자와 일치해야 한다.
- `src`: 구조 JSON을 기준으로 한 로컬 상대경로이다. URL, 상위 경로 이동, manifest 디렉터리 밖으로 나가는 심볼릭 링크는 허용하지 않는다.
- `width`, `height`: 원본의 논리 크기이다. 함께 지정한다. PNG/SVG에서 크기를 읽을 수 있더라도 가능하면 명시한다. HTML에는 실제 고정 화면 크기를 명시한다. 16:9로 임의 왜곡하지 않는다.
- `alt`: 원본 내용을 설명하는 대체 텍스트이다. 이미지의 모든 정보를 스크린리더가 자동으로 읽을 수 있는 것은 아니다. 필요한 경우 별도 상세 텍스트 자료를 제공한다.
- `notes`: 발표자를 위한 메모이다. 노트 패널은 현재 화면에 표시되므로 화면 공유 시 노출된다.
- HTML의 `poster`: 실제 HTML을 렌더링해 얻은 PNG 또는 SVG 미리보기이다. 파일 이름만 다른 임의 이미지를 포스터로 사용하지 않는다.
- SVG의 외부 참조: 허용하지 않는다. `<image href="logo.png">`, `xlink:href`, `url(../fonts/x.woff2)`처럼 `#`이나 `data:`로 시작하지 않는 참조가 있으면 컴파일이 실패한다. 브라우저도 `<img>`로 표시하는 SVG의 외부 자원을 차단하므로 통과시켜도 그림이 비어 보인다. `canvas.mjs inline <src> --out <work>`로 사본을 만들어 data URI로 바꾼 뒤 그 사본을 `src`로 쓴다. 원본은 고치지 않는다.
- 같은 자산을 여러 슬라이드에 인라인하면 그만큼 생성물이 커진다. 합계가 256 KB를 넘으면 빌드가 중복 횟수와 크기를 경고한다. 경고는 실패가 아니며, 자산 해상도를 줄일지 그대로 둘지는 판단해서 정한다.
- 인라인하면 의미가 달라지는 HTML은 거부한다. 외부 스크립트의 `defer`·`async`는 인라인 뒤 효력이 없어지고, 스타일시트의 `media`는 인라인 뒤 모든 매체에 적용된다. 둘 다 오류이며, 저자가 스크립트를 직접 인라인하거나 규칙을 `@media`로 감싸야 한다.
- 보안 정책 meta는 `<head>` 안에서 실행 가능한 내용보다 앞에 놓인다. `<head>`보다 앞에 스크립트나 자원 참조가 있는 문서는 정책을 적용할 수 없으므로 거부한다.
- HTML의 `allowScripts`: 기본값은 `false`이다. 스크립트가 있는 HTML을 허용하려면 출처와 코드를 확인하고 `true`를 명시한다. 기본값이 false인 상태에서 스크립트가 있으면 생성기가 오류를 낸다. 자동으로 삭제해 원본이 보존되었다고 주장하지 않는다.

정적 SVG는 `<img>`로 표시하며, HTML에는 `sandbox`를 사용한다. `allow-same-origin`은 주지 않는다. HTML은 로컬 CSS·이미지·폰트·일반 스크립트 파일을 묶을 수 있지만, 모듈 import, 외부 API·CDN, `srcset`, 오디오·비디오, iframe·form, 일부 CSS import 형식은 지원하지 않는다. 오류가 나면 원본을 몰래 수정하지 말고, 독립 실행용 사본으로 의존성을 정리하거나 승인된 PNG 포스터로 대체한다.

탐색 중에는 HTML 포스터를 표시한다. HTML 슬라이드를 선택하면 그 한 장을 iframe으로 표시하며, 직접 조작 버튼을 켜야 마우스 입력을 받는다. 슬라이드 쇼에서는 현재 HTML 슬라이드를 원본 논리 크기에서 화면에 맞게 축소하고 바로 조작할 수 있다. 화면에는 항상 활성 iframe을 하나만 둔다. 다른 슬라이드로 이동하면 내부 상태가 초기화될 수 있다. 데이터 입력을 저장하는 업무 앱을 이 실행기에 넣는 것은 기본 용도가 아니다.

슬라이드 카드는 원본 화면만 담는다. 제목 막대와 형식 표시는 없고 모서리는 직각이며, 카드 크기는 원본 비율 그대로 480px 폭에 맞춘 값이다. 제목은 목차·이동 경로·발표 노트·접근성 이름에만 쓰이므로, 전체 윤곽에서 장면을 구별하려면 원본 슬라이드 안에 제목이 있어야 한다. 캔버스에서 카드를 한 번 누르면 그 장면으로 확대한다. 화면을 끌어 이동한 뒤에는 확대하지 않는다.

## 슬라이드 쇼와 판서

발표 화면은 슬라이드 쇼 하나이다. 별도의 발표 모드는 없다. 슬라이드 쇼는 현재 경로 커서의 슬라이드를 원본 비율로 화면에 가득 채우고, 도구 막대만 아래에 반투명으로 겹친다. 막대는 화면 영역을 차지하지 않으며 포인터를 올리거나 초점이 들어오면 진해진다.

도구를 고르지 않는다. 마우스 움직임 자체가 도구이다.

| 동작 | 결과 |
|---|---|
| 슬라이드 위에서 움직인다 | 레이저 점이 커서를 따라오고 커서는 숨는다. |
| 760ms 동안 멈춘다 | 레이저가 사라진다. |
| 8px 넘게 끈다 | 강조 상자가 실시간으로 그려지고 손을 떼면 그 자리에 남는다. |
| 끌지 않고 한 번 누른다 | 상자가 사라진다. |
| 다음 장으로 넘어간다 | 상자가 사라진다. |

상자는 화면에 하나만 둔다. 새로 끌면 이전 상자를 대체한다. 좌표는 화면 기준이고 아무것도 저장하지 않는다. 되돌리기나 지우기 버튼이 없는 이유는 남는 것이 없기 때문이다.

레이저와 상자의 색은 인포그랩 로고의 라임에서 틸로 이어지는 색을 쓴다. 테두리는 라임 `#8CC440`, 바깥 번짐은 틸 `rgba(7,140,144,.9)`이다. 상자에는 어두운 1px 윤곽을 더해 밝은 슬라이드에서도 경계가 보이게 한다.

HTML 슬라이드에서는 막대의 `직접 조작`(`C`)으로 이 영역을 걷어 슬라이드가 마우스 입력을 받게 한다. 다른 형식에는 이 버튼이 나오지 않는다.

이동은 방향키·Space·`J`/`K`·숫자 키로 하고 `S`나 Escape로 종료한다. 이전·다음 버튼은 두지 않는다. 막대에는 진행 번호와 종료만 둔다.

## 발표 경로

- `paths`와 각 `steps`는 비어 있을 수 없다.
- 모든 `target`은 실제 슬라이드 ID여야 한다. 그룹 ID와 예약어 `overview`는 허용하지 않는다.
- `id`는 영문자로 시작하고 영문·숫자·`_`·`-`로 구성하며 전체 내용 트리에서 유일해야 한다.
- `duration`은 밀리초 단위의 전환 시간이다. 실행기는 최대 1,500ms로 제한하며, 모션 줄이기가 켜져 있으면 애니메이션을 생략한다.
- 실행기는 전체 윤곽에서 시작한다. `다음 슬라이드`를 누르면 선택한 경로의 첫 번째 슬라이드로 이동한다. 이전·다음 조작은 그룹이나 전체 윤곽을 거치지 않고 슬라이드 사이에서만 이동한다.
- 발표 슬라이드를 이동하면 경로 커서가 바뀐다. 목차나 미니맵으로 다른 장면을 탐색해도 커서는 유지된다. `발표 경로 복귀`로 현재 슬라이드의 시점으로 돌아온다.
- 현재 경로·단계·대상을 URL fragment에 보관한다. 발표 시작 전 상태는 `step=-1`로 기록한다. 같은 HTML 파일을 다시 열면 해당 위치를 복원할 수 있다.
- `슬라이드 쇼`는 현재 경로 커서의 슬라이드에서 시작한다. 시작 전인 `step=-1`에서는 첫 슬라이드로 들어간다. 목차나 미니맵으로 다른 장면을 보고 있더라도 자유 탐색 대상이 아니라 경로 커서를 사용한다.
- 슬라이드 쇼는 브라우저 전체화면을 요청한다. 정책상 거부되면 캔버스 UI를 가린 동일한 슬라이드 전용 화면을 현재 창에서 유지하고 안내를 표시한다. 종료하면 전체화면도 함께 끝낸다.

## 키보드 단축키

| 키 | 동작 |
|---|---|
| `→`, `↓`, `Page Down`, `Space`, `J`, `L` | 다음 슬라이드로 이동한다. |
| `←`, `↑`, `Page Up`, `Shift+Space`, `K`, `H` | 이전 슬라이드로 이동한다. |
| `1`~`9`, `End` | 경로 안의 해당 번호 슬라이드 또는 마지막 슬라이드로 이동한다. |
| `0`, `O`, `Home` | 발표 커서를 유지하면서 전체 윤곽을 탐색한다. |
| `U`, `R` | 상위 그룹 또는 현재 발표 슬라이드로 이동한다. |
| `+`, `-` | 화면을 확대하거나 축소한다. |
| `F`, `S`, `T`, `M`, `N` | 전체화면, 슬라이드 쇼, 목차, 미니맵, 노트를 전환한다. |
| `C` | 슬라이드 쇼에서 HTML 슬라이드 직접 조작을 전환한다. |
| `?`, `Escape` | 단축키 안내를 열거나 현재 모드를 닫는다. |

입력 필드, 선택 목록 또는 직접 조작 중인 HTML 슬라이드가 키보드 입력을 사용하는 동안에는 발표 단축키를 가로채지 않는다. 버튼과 링크에 초점이 있을 때에는 `Space`와 `Enter`를 해당 요소의 기본 조작에 사용한다.

슬라이드 쇼에서는 이전·다음·번호 키·`S`·`C`·Escape를 그대로 사용한다. `allowScripts: true`인 HTML에는 sandbox를 약화하지 않는 키보드 연결 코드를 런타임이 함께 넣어, iframe 안에 초점이 있어도 이 명령을 부모 슬라이드 쇼로 전달한다. 입력 필드에서는 글자·방향키를 가로채지 않는다. 스크립트를 허용하지 않은 HTML에서 초점이 iframe 안으로 들어가면 키보드가 부모에 닿지 않는다. 이때는 막대의 `종료` 버튼으로 빠져나온다. 이동 버튼은 두지 않는다.

## 출력과 수정

`build`는 `index.html`, `manifest.json`, `validation.json`, 라이선스 고지와 출력 소유권 표식을 만든다. `index.html`에는 런타임과 미디어가 포함된다. `manifest.json`은 원본 상대경로를 보존하며 이미지 바이너리를 포함하지 않으므로, 나중에 다시 편집하려면 원본 슬라이드 폴더도 함께 보관한다.

`--force`는 이 도구가 만든 출력 폴더만 교체한다. 추가 파일이나 심볼릭 링크가 있으면 거부한다. 발표 화면의 `구조 JSON 저장`은 원본 구조를 내려받는 기능이며, 드래그로 바뀐 배치를 저장하는 편집 기능은 아니다.
