# 검증 절차와 확인 범위

이 문서는 두 가지만 담습니다. 새 발표를 만들 때 사람이 밟는 절차와, 마지막으로 **실제 측정한** 결과입니다. 과거 버전의 기록은 남기지 않습니다. 무엇이 언제 바뀌었는지는 [CHANGELOG.md](../CHANGELOG.md)에 있습니다.

## 새 발표를 생성할 때

### 데이터 검사

- 입력 목록과 실제 포함 슬라이드의 ID·경로·순서를 대조한다. `inventory`가 `referencedBy`를 붙인 파일은 대개 로고 같은 자산이지만 그 자체로 슬라이드일 수도 있으므로 직접 판단한다.
- 빠진 부록, 경로에 없는 슬라이드, 중복 ID, 깨진 경로를 확인한다. 경고를 0으로 만들기 위해 원본을 조용히 빼지 않는다.
- 모든 그룹의 자식이 경계 안에 들어가는지 확인한다. 포함 관계·배치·발표 경로를 혼동하지 않는다.
- 같은 자료를 다른 구조로 표현했다면 색상만 바뀐 것이 아니라 포함 관계·배치·연결선이 실제로 달라졌는지 확인한다.
- 원본 파일은 수정하지 않는다. `--force`는 이 도구가 만든 폴더에만 쓴다.

### 브라우저 검사

1. `index.html`을 연다. 전체 윤곽에서 모든 슬라이드가 보이고 그룹 위계가 의미에 맞는가.
2. 각 그룹과 슬라이드로 확대하고 상위·전체로 돌아간다. 글자와 모서리가 잘리지 않고 미니맵·도구막대가 내용을 가리지 않는가.
3. 미니맵 클릭·드래그·휠, 빈 공간 이동, 확대·축소 버튼. 이동 뒤에도 발표 단계가 유지되는가.
4. 각 발표 경로를 끝까지 재생한다. 이전·다음이 그룹이나 전체 윤곽을 거치지 않는가. 다른 장면을 탐색한 뒤 `발표 경로 복귀`로 커서가 살아 있는가.
5. 캔버스에서 HTML 한 장을 열고 `HTML 직접 조작`으로 실제 버튼을 누른다. 다른 장면으로 가면 iframe이 해제되는가. 활성 iframe이 항상 하나 이하인가.
6. `슬라이드 쇼`를 누른다. 시작 전에는 첫 장, 발표 중에는 현재 경로 슬라이드에서 시작하는가. 배경 UI가 포커스와 접근성 트리에서 빠지고 원본 비율이 유지되는가.
7. 슬라이드 쇼에서 마우스를 움직여 레이저가 따라오는지, 멈추면 사라지는지, 끌면 강조 상자가 남고 한 번 누르거나 장을 넘기면 사라지는지 확인한다.
8. 슬라이드 쇼의 HTML 슬라이드에서 `직접 조작`(`C`)을 켜고 포인터로 조작한다. iframe 안에 초점을 둔 채 방향키·Escape·`C`가 부모에 전달되는가. 전체화면이 거부되면 현재 창의 슬라이드 전용 화면과 안내가 유지되는가.
9. 방향키·Page Up/Down·Space·J/K·숫자 키와 나머지 보기 전환 단축키, 단축키 대화상자의 포커스, 노트 패널의 화면 노출을 확인한다.
10. URL fragment에 저장된 경로·위치를 새로고침한 뒤 복원한다.
11. 외부 자원 요청, 이미지 decode 실패, 스크립트 오류가 없는지 확인한다. 파일 직접 열기와 네트워크 차단은 별도 항목으로 기록한다.
12. 1920×1080을 기본으로 보고 필요하면 작은 화면도 따로 본다. 실제 화면 크기와 캡처 배율을 혼동하지 않는다.

### 자동화가 놓치는 것

- 브라우저 QA 하네스는 `reducedMotion:'reduce'`로 실행하므로 **카메라 전환 길이와 관련된 회귀를 잡지 못한다.** 전환이 끊기는지 의심되면 모션 축소를 끄고 `.react-flow__viewport`의 `transform`이 바뀌는 마지막 시각을 직접 측정한다.
- 실행기는 `onlyRenderVisibleElements`를 쓴다. DOM의 노드·연결선 개수는 화면에 보이는 것만 센다. 확대한 상태에서 센 값으로 누락을 판정하지 않는다. 전체 윤곽으로 맞추고 렌더가 끝난 뒤 센다.
- 백그라운드 탭은 `requestAnimationFrame`이 멈춘다. 애니메이션을 측정하려면 탭을 전면으로 두거나 같은 호출 안에서 새로 열어 측정한다.
- 확대된 iframe 안의 버튼은 자동화가 내부 문서 좌표를 그대로 반환할 수 있다. 실패한 자동 클릭 하나로 제품이 고장났다고 결론 내리지 않는다.
- 화면보다 큰 영역의 스크린샷이 반복 타일로 나오면 폐기한다. 축소해서 찍은 것을 원본 배율 캡처라고 표시하지 않는다.
- 자동 검사의 `incomplete`는 통과가 아니다. 수동 확인 또는 미확인으로 남긴다.
- 슬라이드가 30장을 넘고 생성물이 수 MB이면 시각 확인 전에 decode 시간을 준다. 크기의 주범은 슬라이드마다 반복되는 로고·폰트이므로 빌드의 중복 인라인 경고를 함께 읽는다.

확인일 2026-09-11, 버전 2.0.1, Chromium. 여기 없는 항목은 이번에 측정하지 않았다는 뜻입니다.

| 단독 파일 | `file://`로 열어 오프라인 상태에서 HTML 슬라이드 조작까지 성공 |

### 미확인·제한

- `[blocked]` 이 환경에서 Fullscreen API 요청이 거부되어 OS 전체화면 전환은 확인하지 못했다. 현재 창의 슬라이드 전용 화면과 안내는 확인했다.
- Safari·Firefox, 모바일 터치·핀치, 수백 장 규모의 메모리·프레임 성능은 이번에 측정하지 않았다.
- 슬라이드 카드는 탭 정지점이 아니다. 캔버스에서 키보드로 개별 장면에 가려면 목차 패널을 쓴다.
- 살균기는 브라우저 파서가 아니다. 판정할 수 없는 입력은 통과가 아니라 거부로 처리한다. 신뢰 경계는 [SECURITY.md](../SECURITY.md)에 있다.
- 드래그 편집, 협업, 전체 캔버스의 SVG·PNG·PDF export는 구현 범위가 아니다.
